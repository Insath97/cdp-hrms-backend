## Overview

CDP HRMS API is the backend REST API for the CDP Human Resource Management System. It powers employee management, attendance (clock-in/out with geofencing), leave, payroll, loans, letters, notifications, and management reports.

- **API versioning:** all endpoints live under `/api/v1`
- **Auth:** JWT bearer tokens with role/permission-based access control
- **Style:** JSON request/response for every endpoint

## Installation

```bash
# 1. Clone the repository (private — access required)
git clone <repo-url>
cd cdp-hrms-api

# 2. Install PHP dependencies
composer install

# 3. Create environment file and generate app key
cp .env.example .env
php artisan key:generate

# 4. Configure .env — set database credentials (see next section)

# 5. Run migrations (+ seeders if available)
php artisan migrate --seed

# 6. Start the development server
php artisan serve
```

API will be available at `http://localhost:8000/api/v1`.

## Authentication

All protected endpoints require a JWT bearer token.

```http
POST /api/v1/login
Content-Type: application/json

{ "email": "user@example.com", "password": "••••••" }
```

Response contains the token. Subsequent requests:

```http
GET /api/v1/employees
Authorization: Bearer <token>
```

- Access is gated by Spatie permissions (e.g. `permission:Attendance Create`) applied per route in controllers.
- Public endpoints (login, forgot-password, backdated attendance, employee QR verification) work without a token.

## API Conventions

**Base URL:** `{APP_URL}/api/v1`

**Success response:**

```json
{
  "status": "success",
  "message": "Operation completed successfully",
  "data": {}
}
```

**Error response:**

```json
{
  "status": "error",
  "message": "Something went wrong"
}
```

Validation errors return `422` with field-level details.

## Scheduled Tasks

Defined in `routes/console.php` — run via Laravel scheduler (cron / Windows Task Scheduler):

| Command | Schedule | Purpose |
|---------|----------|---------|
| `notifications:birthdays` | Daily 08:01 | Birthday emails |
| `notifications:anniversaries` | Daily 08:02 | Work-anniversary emails |
| `attendance:expire-sessions` | Hourly at :01 | Close sessions left open past office end + 1h |
| `attendance:mark-absent` | Daily 21:01 | Auto-mark absent (only if `auto_mark_absent` setting enabled) |

Example cron entry (every minute):

```cron
* * * * * cd /path-to-project && php artisan schedule:run >> /dev/null 2>&1
```

## Fingerprint Devices

- **Webhook:** devices push punches to the fingerprint webhook endpoint (HMAC signature verified) — processed by `FingerprintSDKService`.
- **Sync:** pull device logs via `/fingerprint/sync-attendance` and map them to HRMS attendance records (computes working hours + late status).
- **Manual punch:** `/fingerprint/manual-attendance` for admin-entered clock-in/out.
- Device credentials and office start/grace settings live in `config/fingerprint.php`.
